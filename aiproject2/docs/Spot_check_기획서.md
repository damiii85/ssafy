# SPOT CHECK — AI 창업 입지 분석 서비스

> **슬로건:** 내 가게의 첫 시작, 입지부터 검증하다.  
> **문서:** 서비스 기획서 v1.0  
> **작성 기준:** 2026-10-21  
> **프로젝트:** SSAFY AI 코어 프로젝트 2회차 — RAG 기반 도메인 지식 서비스

---

## 1. 프로젝트 개요

### 1.1 서비스 정의

**SPOT CHECK**는 예비 창업자가 특정 상권의 업종 분포를 이해하고, 실제 창업 후보지의 주변 점포 현황을 비교하며, 공공데이터와 문서 근거를 바탕으로 입지 관련 의사결정을 돕는 **RAG 기반 AI 상권·입지 분석 서비스**이다.

서비스는 **성공 확률이나 매출을 예측하는 도구가 아니다.** 확보된 데이터에서 확인되는 사실, 해당 사실에 대한 해석, 별도 확인이 필요한 사항을 구분하여 제공한다.

### 1.2 문제 정의

- 예비 창업자가 상권 통계, 업종 현황, 창업 가이드 등 분산된 정보를 직접 찾아 해석해야 한다.
- 동일 상권에서도 후보지 주변의 경쟁 점포 구성과 점포 조건은 달라진다.
- 점포 수만으로 입지의 우열을 단정하기 어렵고, 판단 근거와 데이터의 한계를 함께 설명할 필요가 있다.

### 1.3 서비스 목표

1. 선택한 지역의 업종별 점포 수와 공간 분포를 이해하기 쉽게 요약한다.
2. 사용자가 입력한 상세 주소를 중심으로 주변 점포 및 경쟁 환경을 분석한다.
3. 두 후보지를 동일한 기준으로 비교한다.
4. RAG로 관련 외부 문서를 검색하여 해석의 근거와 출처를 제공한다.
5. 임대료, 가시성, 유동인구 등 미확보 정보를 명확히 표시하고 현장 확인 항목을 안내한다.

### 1.4 주요 사용자

- **주 사용자:** 카페·음식점 등 외식업 창업을 검토하는 예비 창업자
- **확장 사용자:** 이전·확장을 고려하는 기존 소상공인

## 2. 서비스 범위와 원칙

| 항목 | MVP 범위 |
|---|---|
| 초기 대상 지역 | 대구 동성로 중심부 |
| 분석 범위 | 현재 수집 기준: 지정 중심점 반경 1km (공식 동성로 경계와 구분) |
| 초기 선택 업종 | 음식점 대분류; 세부 업종은 리포트 및 대화에서 구체화 |
| 분석 대상 | 업종별 상가 분포, 개별 주소 주변 점포, 경쟁 환경 |
| 인터페이스 | 수업 제공 Streamlit 골격을 우선 유지 |
| AI 기능 | 상권 브리핑, 개별 입지 리포트, 근거 기반 질의응답 |
| 확장 기능 | 두 주소 비교, 상세 영업 형태에 따른 맞춤 분석 |

**운영 원칙**

- 사실(집계 결과), 해석(분석 의견), 미확인 사항을 구분한다.
- 카페 밀집이 반드시 불리하거나 유리하다고 단정하지 않는다.
- 근거 없는 입지 점수, 성공 확률, 매출 전망은 제시하지 않는다.
- API 조회 기준일·분석 반경·데이터 출처를 표시한다.
- 상가 API의 업종 분류로 구별할 수 없는 영업 형태(예: 테이크아웃 전문)는 임의 추정하지 않는다.

## 3. 사용자 경험(UX) 흐름

```text
[1] 지역 선택: 대구 > 동성로
       ↓
[2] 대분류 선택: 음식점
       ↓
[3] AI 상권 종합 브리핑 자동 제공
    - 업종별 점포 수
    - 업종별 공간 분포·밀집 구역
    - 데이터로 확인되는 상권 특징
       ↓
[4] 채팅에서 창업 의도·상세 주소 입력
    예: "동성로5길 11 2층에 카페를 열려고 해"
       ↓
[5] 해당 위치의 상세 입지 분석 리포트
    - 반경 300m / 500m 경쟁 점포
    - 주변 업종 구성
    - 강점·위험 요인·확인 필요 사항
       ↓
[6] 필요할 때 AI가 영업 형태 추가 질문
    예: 테이크아웃 중심 / 좌석 중심 / 디저트 중심
       ↓
[7] 두 후보지 비교 및 후속 RAG 상담
    예: "동성로5길 11 2층과 동성로 8-9 중 어디가 나을까?"
       ↓
[8] 근거 문서 및 창업 전 현장 확인 체크리스트 제공
```

처음에는 음식점 전체 상권을 보여주고, 사용자가 채팅에서 '카페 창업' 등 구체적인 업종과 조건을 밝히면 분석을 좁혀 간다. 상세 주소 입력 전부터 과도한 설문을 요구하지 않는다.

## 4. 주요 기능 명세

### F-01. 상권·업종 선택

- 사이드바에서 지역과 업종 대분류를 선택한다.
- MVP에서는 **동성로 / 음식점**을 우선 지원한다.
- 선택 상태 및 대화 기록은 Streamlit `session_state`로 관리한다.

### F-02. AI 상권 종합 리포트

- 선택 상권의 전체 점포 수, 업종별 점포 수와 구성비를 표시한다.
- 식당·카페·주점 등의 공간 분포 및 밀집 구역을 분석한다.
- 지도 시각화는 기능 구현 후 단계적으로 적용한다.
- 밀집도는 점포 좌표를 이용해 계산하며, 공식 업종 분류에 맞춰 집계한다.
- **주의:** 초기 1km 원형 조회 결과를 '동성로 행정·공식 상권 전체'로 표현하지 않는다.

### F-03. 상세 주소 입력 및 위치 확인

- 사용자가 도로명주소와 층수 등 후보지 정보를 자유롭게 입력한다.
- 주소를 좌표로 변환할 수 있는 주소 검색·지오코딩 수단을 연계한다.
- 주소가 모호하거나 변환에 실패하면 확인을 요청한다.
- 층수와 건물 조건은 공공 API로 확인되는 정보와 사용자 입력 정보를 구분한다.

### F-04. 개별 입지 분석 리포트 — 핵심 특화 기능

**입력:** 후보지 주소, 관심 업종, 선택적 영업 형태

**출력 항목:**

1. 후보지 기본 정보: 주소, 좌표, 분석 업종, 반경, 기준일
2. 경쟁 환경: 반경 300m·500m 동종 점포 수 및 주변 업종 분포
3. 공간 분포: 후보지 주변 업종 밀집 구역
4. 입지 해석: 데이터로 확인된 강점과 위험 요소
5. 미확인 정보: 유동인구, 임대료, 매출, 가시성 등
6. 관련 외부 문서 근거: 문서 제목, URL 또는 PDF 페이지
7. 창업 전 현장 확인 체크리스트

**리포트 구성 원칙:** 통계는 Python에서 계산하고, LLM은 제공된 통계와 검색된 근거 문서를 해석한다. LLM에 점포 목록의 수량을 직접 세도록 맡기지 않는다.

### F-05. 두 후보지 비교

- 두 주소를 각각 좌표로 변환한다.
- 같은 반경·업종 기준으로 지표를 계산하여 나란히 표시한다.
- 동종업체 수, 업종 다양성, 점포 조건 및 추가 조사 항목을 비교한다.
- 확보된 데이터만으로 우열을 결정할 수 없으면 판단을 유보하고 이유를 설명한다.
- **개발 우선순위:** 기본 RAG와 단일 입지 리포트가 완성된 뒤 구현한다.

### F-06. 근거 기반 AI 채팅

- 사용자는 상권 또는 선택한 항목에 대해 자연어로 질문한다.
- RAG가 관련 메타데이터와 외부 문서 청크를 검색한다.
- 답변의 주요 주장에 근거 번호를 표시하고 실제 사용한 출처만 노출한다.
- 근거가 부족한 질문에는 추측하지 않고 '확인되지 않음'을 알린다.
- 상권·선택 항목별 대화 기록을 분리하여 유지한다.

### F-07. 자연어 조건 기반 항목 탐색

- 예: "동성로에서 카페가 밀집한 구역 주변 상가를 보여줘."
- 상가 메타데이터 검색 후 사용자의 조건에 맞는 후보만 제시한다.
- 결과 항목을 선택하면 해당 항목에 관한 채팅을 이어갈 수 있다.
- 이 기능은 프로젝트 명세서의 **F2011 필수 요구사항**을 충족하기 위해 별도로 구현·검증한다.

### F-08. 오류·진행 상태·주의 안내

- 데이터 수집·문서 검색·답변 생성 진행 상태를 표시한다.
- API 키 누락, 색인 미완료, 검색 결과 없음, 주소 인식 실패를 안내한다.
- 입지 분석은 창업 성공을 보장하거나 전문가 현장 조사를 대체하지 않는다는 문구를 표시한다.

## 5. 입지 분석 지표

| 분석 영역 | 세부 지표 | MVP 가능 여부 / 비고 |
|---|---|---|
| 상권 규모 | 전체 상가 수, 업종별 점포 수 | 상가 API 데이터로 집계 가능 |
| 경쟁 환경 | 반경 300m·500m 동종업체 수 | 좌표·업종코드 기반 계산 |
| 업종 구성 | 식당·카페·주점 등 비중 | 실제 제공되는 업종 분류 확인 필요 |
| 공간 분포 | 업종별 점포 밀집도 | 좌표 기반 분석 가능, 기준 정의 필요 |
| 상권 변화 | 개·폐업 추이, 공실 | 현재 수집 데이터만으로 판단 불가 |
| 수요 | 유동인구, 거주·직장인구 | 별도 데이터 확보 필요 |
| 소비 | 추정 매출, 객단가 | 별도 데이터 확보 필요 |
| 접근성 | 보행 동선, 교통 접근성, 가시성 | 별도 데이터 또는 현장 조사 필요 |
| 점포 조건 | 층수, 면적, 출입구, 간판 | 사용자 입력 및 현장 확인 |
| 비용 | 보증금, 월세, 권리금 | 사용자 입력 또는 별도 자료 필요 |
| 사업성 | 손익분기점 시뮬레이션 | 입력 데이터 확보 후 확장 |

**데이터 해석 주의:** 업종 밀집은 경쟁이 치열하다는 신호일 수 있지만, 동시에 상권 활성화의 징후일 수도 있다. 점포 수만으로 수요·매출·창업 성공 가능성을 추정하지 않는다.

### 6.1 상가업소 공공데이터

- **출처:** 소상공인시장진흥공단 상가(상권)정보 OpenAPI

- **현재 수집 결과:** 8,496건 (사용자 로컬 실행 로그 기준, 중복 제거 후)
- **저장 파일:** `data/raw/dongseongro_stores.json`, `data/raw/dongseongro_stores.csv`
- **수집 메타데이터:** `data/raw/collection_metadata.json`
- **주요 필드:** `bizesId`, `bizesNm`, `indsLclsCd/Nm`, `indsMclsCd/Nm`, `indsSclsCd/Nm`, `rdnmAdr`, `lon`, `lat`
- **현재 상태:** 로컬 API 수집 성공; 업종별 집계·데이터 정합성 검증·Vector DB 색인은 미완료

> 이 8,496건은 **동성로 공식 상권 전체의 점포 수가 아니라, 지정 중심점 반경 1km 조회 결과**이다. 또한 명세서의 '100건 이상 항목 확보'를 위한 원천 데이터는 확보했으나, F2001의 색인 텍스트 구성 및 F2002의 임베딩 색인은 아직 별도로 구현해야 한다.

### 6.2 외부 문서(RAG 2)

- **예정 출처:** 공공기관의 창업·상권·입지 관련 가이드 및 공개 PDF 문서
- **용도:** 입지 판단 기준, 창업 전 체크리스트, 상권 통계 해석에 관한 근거 제공
- **수집 조건:** 문서 제목, 발행기관, 원문 URL 또는 파일명·페이지, 수집일, 이용 조건 기록
- **현재 상태:** 실제 문서 목록과 수집·색인 여부는 확정 전

**핵심 구분:** 상가 API의 점포 수·좌표 등 정형 데이터는 Python으로 정확히 계산한다. 외부 설명 문서는 RAG 검색으로 해석의 근거를 제공한다.

## 7. RAG 및 시스템 설계

### 7.1 기술 스택

| 영역 | 기술 |
|---|---|
| 언어 | Python 3.10+ |
| UI | Streamlit (수업 제공 `step7_skeleton.py` 구조 참고) |
| LLM/RAG | LangChain, OpenAI 연동 |
| 파이프라인 | LangGraph (`retrieve` / `generate`) |
| Vector DB | ChromaDB |
| 수집·분석 | requests, pandas, 좌표 기반 거리 계산 |
| 문서 처리 | PDF 텍스트 추출, 청킹, 임베딩 |
| 설정·보안 | `.env`, `python-dotenv`, `.gitignore` |

### 7.2 컬렉션 구조(안)

**컬렉션 A: `store_meta` — RAG 1**

- **항목 단위:** 개별 상가업소 1건
- **식별자:** `bizesId` 기반 고정 ID
- **검색 텍스트:** 상호명 + 업종 대·중·소분류 + 도로명주소 + 지역 정보
- **메타데이터:** 상가 ID, 업종코드, 주소, 위도·경도, 출처 등
- **목표:** 100건 이상 색인, 재실행 시 중복 방지

**컬렉션 B: `location_docs` — RAG 2**

- **항목 단위:** 외부 문서의 청크
- **식별자:** 관련 항목 ID + 문서 ID + 청크 번호 등 충돌 방지 규칙
- **메타데이터:** 문서 제목, URL/파일명, 페이지, 문서 유형, 수집일, 관련 항목
- **목표:** 관련 문서의 검색·근거 표시

**설계 시 확인 사항:** 명세서에서는 선택 항목 자체를 다루는 문서를 우선 수집·색인하도록 요구한다. 개별 상가를 항목으로 정의한 경우, 상가마다 직접 관련된 외부 문서를 어떻게 연결할지 별도 설계·검증이 필요하다. 일반 창업 가이드만으로 해당 요구사항을 충족했다고 간주하지 않는다.

### 7.3 필수 프롬프트 3종

1. **검색어 추출 프롬프트:** 선택한 항목·질문에서 외부 문서 검색어를 구조화된 형식으로 추출한다.
2. **문서 후보 선별 프롬프트:** 검색된 후보 문서 중 관련성이 높은 자료를 선별한다.
3. **근거 기반 답변 프롬프트:** 검색된 메타데이터와 문서에 근거하여 답변하고, 근거 번호를 인용한다.

### 7.4 RAG 실행 흐름

```text
사용자 질문 + 선택 상권/항목
          ↓
[프롬프트 1] 검색어 추출
          ↓
외부 문서 검색 및 후보 수집
          ↓
[프롬프트 2] 후보 문서 선별
          ↓
문서 본문 수집 → 청킹 → ChromaDB 색인
          ↓
LangGraph retrieve 노드
  - 선택 항목 메타데이터 포함
  - 외부 문서 유사도 검색
  - 결과 병합·중복 제거·Top-k 적용
          ↓
LangGraph generate 노드
  - 계산된 상권 통계와 검색 근거 활용
  - [근거 n] 표시 / 미확인 사항 구분
          ↓
Streamlit 답변·출처 표시
```

청크 크기, 중복 길이, Top-k는 설정 파일에서 변경할 수 있게 설계한다. 이미 수집한 검색어는 캐시를 통해 불필요하게 재수집하지 않는다.

## 13. 성공 기준 및 검증 계획

1. 상가 항목 100건 이상이 로드·색인되고, 재색인해도 중복 증가가 없어야 한다.
2. 외부 문서를 별도 컬렉션에 색인하고 검색할 수 있어야 한다.
3. 세 프롬프트와 LangGraph 두 노드가 요구사항대로 동작해야 한다.
4. 사용자의 질문에 대한 답변과 인용 출처가 일치해야 한다.
5. 문서에 없는 질문에는 추측하지 않아야 한다.
6. 항목을 바꾸면 대화가 섞이지 않아야 한다.
7. 자연어 조건 탐색과 입지 리포트가 동작해야 한다.
8. 키 누락·색인 없음·검색 실패 등 예외 상황을 사용자에게 안내해야 한다.
9. 요구사항 대조표, 테스트 결과, 실행 화면, README, RAG 설계문서를 제출한다.

## 14. 최종 서비스 메시지

**SPOT CHECK는 '어디에 창업하면 성공할까?'에 근거 없는 확답을 주는 서비스가 아니다.**

대신 **'이 위치에 어떤 상가들이 있고, 경쟁 환경은 어떠하며, 창업 전에 무엇을 더 확인해야 할까?'**라는 질문에 공공데이터와 문서 근거를 활용해 답하는 **AI 창업 입지 분석 도우미**를 지향한다.
