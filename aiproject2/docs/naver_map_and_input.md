# 네이버 지도와 두 가지 입력 유형

## 네이버 지도 설정

NAVER Cloud Platform Maps에서 Application을 생성하고 **Dynamic Map**을 선택한다.
Web 서비스 URL에 실제 접속 주소를 등록한다. 로컬 확인에는 `http://localhost:8501`을 사용하며,
`127.0.0.1` 또는 내부 네트워크 주소로 접속한다면 해당 주소의 등록도 확인한다.
공식 안내: https://navermaps.github.io/maps.js.ncp/docs/tutorial-1-Getting-Client-ID.html

`.env`에 지도용 Client ID를 추가한다.

```dotenv
NAVER_MAP_CLIENT_ID=발급받은_지도_Client_ID
```

`NAVER_CLIENT_ID`라는 이름도 지원한다. 두 이름이 모두 있으면 `NAVER_MAP_CLIENT_ID`를 우선한다.
`NAVER_CLIENT_SECRET`은 지도 표시 코드에서 읽거나 브라우저로 전달하지 않는다.

Dynamic Map은 브라우저에서 공개 식별자인 Client ID(`ncpKeyId`)를 사용한다.
Client Secret은 이 지도 표시 기능에 필요 없으며 브라우저로 보내지 않는다.
키가 없으면 연결 준비 상태를 표시한다. 키 설정 후 페이지를 새로고침한다.
기존 `st.map`은 제거하고 `st.html(unsafe_allow_javascript=True)`의 고정 스크립트로 네이버 지도 SDK를 로드한다.
사용자 주소·레이블은 이스케이프한 JSON 데이터와 textContent로만 전달한다.
iframe의 `about:srcdoc`에서는 네이버 인증에 잘못된 서비스 주소가 전달되므로 사용하지 않는다.
SDK의 script.onload 이후에 지도를 생성하고 SDK는 페이지당 한 번만 로드한다.
2026-10-21 비표시 Edge 브라우저에서 인증 HTTP 200, 지도 타일과 마커 표시를 실제 확인했다.
주소 분석 위치 또는 추천 후보들에 마커와 분석 반경을 표시한다.
이 변경은 지도 표시이며 네이버 Geocoding API 연결을 의미하지 않는다.

## 입력 유형

1. `중앙대로 412-21에서 카페 창업하고 싶어` → 주소 분석. 주소와 업종을 차례로 입력해도 된다.
2. `동성로에서 카페를 하고 싶은데 어디가 좋을까?` → 스팟 내 후보지 추천. 주소가 필요 없다.

이전 주소 분석 후 추천으로 바꾸면 이전 주소를 제거한다. 업종은 실제 CSV 분류로 검증한다.
모호한 입력은 주소 분석과 추천 중 원하는 방식을 확인하도록 안내한다.
스팟은 사이드바 선택을 기준으로 한다.

## 후보지 추천 기준

수집된 상가를 200m 격자로 나누고 각 격자의 기존 건물 좌표를 비교 중심으로 삼는다.
후보지 주변 분석 원 전체가 수집 범위에 들어오는 곳만 비교한다.
주변 상가 10곳 이상인 후보 중 상가 수가 후보 중앙값 이상인 곳을 선정하고,
선택 업종 점포 비중이 낮은 순으로 최대 3곳을 제시한다. 동률이면 주변 상가 수가 많은 순이다.
후보가 붙어 있지 않도록 후보 간 최소 분석 반경만큼 간격을 둔다.
집계는 벡터 검색 표본이 아닌 전체 CSV를 사용한다.

이는 주변 상가 밀집과 경쟁 비중을 비교하는 탐색 기준이며 검증된 입지 평가 모델은 아니다.
경쟁 비중이 낮으면 수요가 부족할 수도 있다. 유동인구·매출·임대료·가시성·층수는 미반영이다.
제시 주소는 비교 중심 건물로, 빈 점포나 임대 가능한 매물이 있다는 의미가 아니다.
지도에 표시된 후보를 확인한 뒤 상세 주소 분석과 현장 조사를 진행한다.

`스팟별 데이터 확보 현황` 표는 화면에서 제거했다. 내부 수집 상태 및 데이터 파일은 보존한다.
