
## 김대호 
1. 주요 기능 설명
1) 실시간 토스증권 동적 크롤링 및 종목 자동 매칭
사용자가 일부 키워드(예: '삼성')만 입력해도 백그라운드 Selenium 크롤러가 실제 토스증권 메인 페이지에 접속하여 상단 검색창을 조작합니다. 가장 상단에 노출된 공식 종목 페이지로 이동한 뒤, 동적으로 변하는 웹 페이지 타이틀 및 주소에서 정확한 공식 종목명('삼성전자')과 종목 코드('A005930')를 자동으로 파싱해 추출합니다.

2) 커뮤니티 댓글 자동 수집 및 스크롤 핸들링
토스증권 종목별 커뮤니티 페이지로 이동하여 자바스크립트(SPA) 기반의 내부 스크롤 상자(Viewport)를 추적합니다. 요소가 깨지지 않는 최적의 CSS 선택자를 활용해 스크롤을 내리며 실시간으로 생성되는 댓글 데이터를 중복 없이 지정한 목표 개수까지 안정적으로 모읍니다.

3) 정규표현식 기반 local 전처리 및 LLM 비속어/선동 필터링
수집된 원본 댓글은 정규표현식(Regex)을 거쳐 이모지, 깨진 특수문자, 의미 없는 자음/모음, 짧거나 긴 노이즈 텍스트를 우선 차단합니다. 이후 OpenAI(GMS) LLM을 연동하여 욕설, 비방, 조롱, 근거 없는 매수·매도 선동글의 인덱스만 정확히 선별 및 검증한 뒤 제거함으로써 깨끗한 정제 댓글 세트를 생성합니다.

4) LLM 기반 데이터 증강(Augmentation) 및 출처 통합
감성 분석 모델 학습 데이터를 풍부하게 만들기 위해 정제된 댓글의 주가 방향, 숫자 단위, 투자 심리 맥락을 유지한 채 유의어로 확장된 새 문장을 LLM으로 자동 생성합니다. 원본 및 증강 데이터는 추적 가능하도록 source('cleaned' / 'augmented') 태그와 원본 인덱스를 포함한 통합 구조로 관리됩니다.

5) Server-Sent Events(SSE) 실시간 파이프라인 스트리밍 및 4단계 UI 카드 렌더링
Selenium과 LLM 실행에 소요되는 시간을 고려하여 Django의 StreamingHttpResponse와 브라우저의 EventSource를 연결했습니다. 사용자에게 '댓글 수집 중...', 'LLM 필터링 중...'과 같은 단계별 진행 상태를 실시간 로딩 애니메이션으로 전달하며, 작업 완료 시 원본·전처리·증강·최종 결과를 한눈에 비교할 수 있는 4단계 카드 UI를 화면에 시각화하고 최종 데이터를 DB에 일괄 저장합니다.

2. 학습 내용
1) 동적 웹 페이지(SPA) 크롤링과 예외 처리 기법
자바스크립트로 화면을 실시간 렌더링하는 Single Page Application 특성상 발생하는 대기 시간 문제를 WebDriverWait와 expected_conditions로 해결했습니다. 특히 주식 시장 장중에 탭 타이틀(현재가 표시)이 동적으로 바뀌는 레이스 조건(Race Condition)을 분석하여, 데이터가 완전히 로딩되는 시점을 조건문으로 제어하는 실제 웹 환경의 예외 처리 기술을 익혔습니다.

2) Django 비동기 스트리밍(SSE) 및 파이프라인 아키텍처 구축
일반적인 HTTP 요청-응답 구조에서는 장시간 걸리는 크롤링/LLM 작업 시 브라우저 타임아웃이 발생할 수 있음을 이해했습니다. 이를 극복하기 위해 yield generator를 기반으로 한 SSE(Server-Sent Events) 방식을 구현하여 백엔드의 처리 상태를 클라이언트에 실시간 이벤트 스트림으로 전송하는 비동기 UX 설계 방식을 습득했습니다.

3) LLM 환각(Hallucination) 방지 및 안전한 데이터 파싱
LLM에게 데이터 가공을 맡길 때 텍스트 전체를 재출력하게 하면 원본이 훼손되거나 형식이 깨질 수 있음을 확인했습니다. 이를 막기 위해 "제거할 댓글의 인덱스 번호 배열만 반환"하도록 프롬프트를 정교화하고, parse_json_array 함수를 통해 응답값의 타입과 범위를 2중 3중으로 검증(Sanitization)하는 안전한 AI 데이터 파이프라인 구성법을 배웠습니다.

4) Django JSONField를 활용한 유연한 데이터베이스 모델링
가변적인 크기의 리스트(댓글 목록)나 딕셔너리 구조(IQR 임계값, 실행 시간 통계)를 RDBMS의 일반 컬럼으로 다루기 힘든 한계를 경험했습니다. Django의 JSONField를 도입하여 파이썬의 구조화된 객체를 손실 없이 데이터베이스 한 행(Row)에 깔끔하게 저장하고 관리하는 DB 모델링 기법을 체득했습니다.

3. 느낀 점
이번 프로젝트를 진행하며 단순히 단일 스크립트로 데이터를 수집하는 것을 넘어, 백엔드 서버 웹 프레임워크(Django)와 AI 파이프라인, 그리고 프론트엔드 UI까지 하나로 연결되는 완성도 높은 풀스택 데이터 시스템을 구축해 볼 수 있었습니다. 특히 웹사이트의 예기치 않은 구조 변경이나 동적 타이틀 변화 같은 실무적인 변수들을 하나씩 분석하고, 대기 로직과 조건식을 수정해가며 안정적인 크롤러로 발전시켜 나가는 과정에서 큰 성취감을 느꼈습니다.
또한 규칙 기반(Deterministic)의 정규표현식 전처리와 확률 기반(Nondeterministic)의 LLM 전처리를 상호보완적으로 결합했을 때 데이터 가공의 효율성과 정확도가 극대화된다는 점을 깨달았습니다. 작업 시간이 다소 소요되는 파이프라인 특성을 고려해 실시간 스트리밍 UI를 적용함으로써 사용자 관점의 UX까지 고민해 볼 수 있었던 뜻깊은 프로젝트였습니다.

## 박예담

1. 주요 기능 설명

1) 사용자 입력 기반 종목 검색 및 댓글 수집
사용자가 입력한 회사명으로 토스증권을 검색하고, 최상단에 선택된 종목의 공식 이름과 종목 코드를 추출하도록 구현했습니다. 해당 종목의 커뮤니티로 이동한 뒤 내부 스크롤을 반복하며 중복을 제외한 댓글 20개를 수집했습니다.

2) 팝업 및 동적 페이지 변화에 대한 예외 처리
종목 검색 후 나타나는 안내 팝업을 닫고 커뮤니티 탭으로 이동하도록 처리했습니다. 화면 갱신으로 기존 요소를 사용할 수 없을 때는 요소를 다시 찾도록 보완했으며, 실제 사이트의 제목 형식에 맞춰 종목명 추출 로직을 수정했습니다.

3) 로컬 정제 및 GMS 기반 부적절 댓글 필터링
결측치, 이모티콘, 특수문자와 불필요한 패턴을 제거하고 정제 후 길이가 5~76자인 댓글만 유지했습니다. 이후 GMS LLM으로 부적절한 댓글의 번호를 받아 검증한 뒤 제거했습니다. 로컬 정제를 먼저 수행하여 LLM에 전달하는 데이터양을 줄였습니다.

4) 의미 기반 데이터 증강 및 전체 파이프라인 연결
정제된 댓글의 의미와 감정, 숫자 정보를 유지하도록 증강 프롬프트를 구성하고 응답 개수와 문자열 형식을 검증했습니다. 기능별 함수를 `run_pipeline.py`에서 순서대로 호출해 한 번의 실행으로 수집부터 증강까지 처리하고, 원본과 단계별 결과를 구분하여 반환하도록 구성했습니다.

5) 실행 결과 검증 및 산출물 정리
실제 검색부터 댓글 수집, 정제, 증강과 웹 결과 출력까지 실행 흐름을 확인했습니다. 진행 상태와 단계별 결과 화면을 [capture](capture/) 폴더에 정리했습니다.

2. 학습 내용

1) 동적 웹 페이지 크롤링과 조건 기반 대기
동적 페이지에서는 단순히 일정 시간을 기다리는 것보다 필요한 요소나 새로운 댓글이 나타나는 조건을 기다리는 방식이 효율적이라는 것을 배웠습니다. 화면에 보이는 위치와 실제 스크롤 가능한 요소가 다를 수 있어 댓글을 감싸는 부모 요소를 확인해야 한다는 점도 이해했습니다.

2) 오류 로그와 실제 화면을 활용한 문제 해결
StaleElementReferenceException, 팝업에 가려진 요소, 변경된 페이지 제목 등 서로 다른 원인이 비슷한 수집 실패로 나타날 수 있음을 경험했습니다. 로그와 실제 화면을 비교하며 어느 단계에서 멈췄는지 확인하고, 재시도 횟수와 종료 조건을 정하는 방법을 익혔습니다.

3) 정규표현식과 LLM을 결합한 데이터 전처리
길이, 공백, 특수문자처럼 명확한 기준은 로컬 코드로 처리하고, 문맥이 필요한 부적절 표현 판단은 LLM에 맡기는 역할 분담을 배웠습니다. 또한 LLM 응답은 JSON 형식뿐 아니라 번호의 타입과 범위, 증강 문장의 개수까지 검증해야 한다는 점을 이해했습니다.

4) 함수 분리와 Django 연동을 고려한 데이터 구조 설계
수집·정제·필터·증강을 함수로 분리하고 결과를 딕셔너리로 통일하면 단계별 확인과 재사용이 쉬워진다는 것을 배웠습니다. Django 담당 팀원이 회사명을 전달해 전체 처리를 호출하고, 반환된 결과를 화면과 DB에 사용할 수 있도록 입력값과 결과 구조를 맞추는 협업을 경험했습니다.

3. 느낀 점

처음에는 댓글을 많이 가져오는 것이 핵심이라고 생각했지만, 실제로는 팝업과 페이지 구조 변화에 대응하면서 필요한 데이터를 안정적으로 수집하는 과정이 중요했습니다. 특히 스크롤이 움직이지 않거나 종목명 추출 단계에서 멈추는 문제를 로그와 화면으로 확인하고 해결하면서, 추측보다 실행 결과를 바탕으로 원인을 찾는 태도가 필요하다고 느꼈습니다.

팀원이 맡은 Django 기능과 연결하기 위해 함수의 입력값과 반환 구조를 맞추면서 각자 만든 코드가 하나의 서비스로 이어지는 과정을 이해했습니다. 처리 순서를 조정하고 불필요한 대기를 줄이는 것뿐 아니라 원본과 가공 결과를 보존하는 것도 중요했습니다. 앞으로는 실행 속도와 함께 정제 및 증강 과정에서 댓글의 문맥과 의미가 유지되는지도 더 꼼꼼하게 확인하고 싶습니다.
